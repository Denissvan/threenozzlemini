# 原模组点检自动化及专用料盘方案草案

状态：方案讨论，尚未实现；机械布置和新协议未确认。三嘴技改暂存节点：2583fb4。

## 本次范围澄清：环境点检与模组点检分开

用户明确本次将原先到时后人工开启、人工供料的模组点检转换为自动执行，不新增另一套独立点检业务。环境点检保持现有实现。

环境点检链路：AutoInspectionParameter（EmbeddedAutoCheck.cs）的ifcheckontime/ifcheckontime_enabled；环境定时调度；WS中在指定工站/测试步骤执行ReadStandardBoardInfo、AutoCheckPass和AutoCheckLightPass，检查距离、照度、色温等。不能因为名字包含AutoCheck就将其改为模组供料触发。

模组点检链路：PT_SET.AutoChkEn/AutoChkSelectWs、VAR.isAutoChkMode、WS.AutoChkCnt/ListChkTemp；WS.WaitTestResult识别279/276到时提示，FrRun.cbCheckModEn_CheckedChanged人工开启；WS.PutModShowMsg要求人工上专用点检模组并确认；既有GetPcChkInfo、SetPcAutoChk、GetPcChkResult、SetPcPrductMod负责项目、模式和结果。应在此链路上自动化人工环节，保留原有测试项目语义。

FrMain另外存在CheckTimeMorning/Evening到时提示人工清料并上传点检信息的入口；它与测试PC返回279/276是不同代码入口。最终触发来源需按现场使用方式统一，避免同一次模组点检被计时提示和PC结果各触发一次；不将环境定时器合并进来。

改造重点：模组到时通知登记待执行 → 绑定下一未预取的目标批次 → 正常交换取点检模组并卸普通成品 → 复用原模组点检项目/协议执行与结果判断 → 正常交换归还点检样品并取普通料 → 自动完成模式恢复。全过程不以ClearMt清普通料。手动开启可保留为相同模组点检任务的人工触发入口，而非维护两套重复业务。

## 用户已确认的执行原则

不清普通料、不等待整机空料。正常上下料继续，点检作为后续一轮的指定上料任务，从专用点检盘取料替代该轮对应的普通料。旧方案中的整机清料建议撤回。

## 建议流程

当前生产轮正常完成 → 登记点检请求并确定目标测试批次 → 目标批次预取改用点检盘 → 正常交换时卸出普通成品、装入点检料 → 目标测试PC按正确参数执行点检 → 立即读取并保存结果 → 后续正常交换卸出点检料、装入下一轮普通料或下一组点检料 → 点检料归指定点检穴位；普通成品仍按正常OK/NG规则落盘。

请求线程只登记任务。新任务以目标工站/测试PC、测试批次及穴位计划绑定，不在请求瞬间直接改变全局模式或已预取物料身份。具体覆盖整批还是部分穴位，须与测试PC模式作用范围核对，不能默认允许同一PC的一轮中混测普通料和点检料。

三嘴代码会在开盖前预取，ThreeNozzlePrefetch先建立计划，再调用ThreeNozzlePreparePair。点检料源必须在目标测试批次预取前冻结。建议请求到达时若该批已经预取普通料，则这批照常完成，点检安排到下一未开始预取的完整批次；不能取到一半临时改源。此延后规则需确认是否满足“下一轮”的协议要求。

模式切换针对目标测试PC，在其当前普通测试完成后执行，等待SetFactoryMode重启Ack并回读确认，点检料装夹且PC就绪后才能启动点检。机械上下料不需要清场，但不能保证测试软件重启完全不增加等待；未完成模式恢复时不能用点检参数测试普通料。其他PC是否可继续由实际测试PC与工站的对应关系决定。

接收、计划已绑定、已装夹、测试结束、样品已归还分别记录。点检异常保留当前在机普通料/点检料身份，不自动切入清料分支。

## 点检料和三嘴动作

点检料具有独立身份：任务号、样品号、点检类型、源盘/源穴、当前所在嘴/夹具、轮次和结果。任务内记录供料和归还位置，不能依靠res判断去OK/NG盘。建议可复用点检样品回原穴，失败样品保留异常状态；此处需用户确认实际料去向。

点检盘位置按可取放机械臂保存XY、工艺Z、必要U以及穴位映射；工艺Z使用本轮已建立的逐嘴补偿，避免另设一套Z算法。固定盘不应强行调用普通料仓的升降/换盘动作，移动盘则需独立就绪和到位确认。

普通料切点检料、点检轮间换料、点检料切回普通料均复用正常两片交换和三嘴周转。取料来源由目标批次决定；卸料去向由被取出物料的身份决定，同一交换中两者可以不同。不得仅用当前全局点检标志决定所有吸嘴的落盘位置。

## 协议边界（字段建议，不是已约定报文）

请求至少需表达唯一任务号、目标工站/测试PC、点检类型或轮次计划、样品选择、开始条件。提供接收/拒绝、当前阶段、测试结果、故障、最终完成的响应，并明确超时及取消。

相同任务号重发只返回已有状态，不重复取料。不同任务冲突第一版建议返回忙；断线后查询原任务状态，不自动新开任务。未确认PC测试已结束时不取料；测试结果读取与机械归还解耦，若沿用旧DLL需遵守其结果窗口。

模组点检复用原项目、模式及结果处理，手动按钮可保留为同一任务的人工触发入口；自动路径替换例行人工上料/确认步骤。同一次到时事件不能同时触发旧弹窗和新任务。新协议接收位置需根据测试端最终协议确定，不能默认279/276即为新协议。

## 软件改动方向

1. 增加点检任务协调器，管理请求、目标批次绑定、供料、测试、回盘、恢复及异常状态；负责与三嘴协调器的模式边界。
2. 增加点检盘配置和物料来源/归还策略。ThreeNozzlePreparePair从选定料源获取指定穴位；实际取放复用XT与现有补偿/避障。
3. WS对接任务规定的测试步骤和结果；将例行人工上料/确认改成任务驱动，保留异常人工处理。
4. 独立点检记录与统计，避免污染正常产量/良率；MES是否上传及上传类型需业务确认。
5. UI增加点检盘示教及穴位/样品配置、自动点检开关、任务阶段/轮次/结果状态。生产中锁定点检盘配置。
6. 异常保留任务号、源穴、在机物料和待执行步骤；断电重启进入待核对状态，不凭内存丢失自动续跑。已有报警及人工恢复机制保留。

## 后续验证

离线验证请求去重、预取前绑定/已预取请求顺延、普通与点检料去向隔离、部分样品缺失、单双片/末批、NG仍回指定穴、断线/取消/重启恢复、统计隔离。实机先验证点检盘坐标/IO/三嘴取放，再联调协议，最后覆盖完整生产→点检→生产闭环。

## 正常生产中插入点检的具体改动方案

### 三种交换过渡

| 交换类型 | 下一批取料来源 | 当前从夹具取出的物料 | 卸料目的地 |
|---|---|---|---|
| 普通生产进入点检 | 点检盘指定样品穴位 | 普通成品 | 原OK/NG盘 |
| 点检结束恢复普通生产 | 普通供料盘 | 点检样品 | 该样品登记的点检归还穴位 |
| 点检轮次之间换样 | 下一轮样品穴位 | 上一轮点检样品 | 上一轮样品登记的归还穴位 |

此表表达料流，不改变ThreeNozzleSequence中已实现的逐穴取旧/放新顺序。对于同一标准样品跨轮复用，必须确认是否允许留在夹具直接重测；若需要归盘再取而该样品尚在夹具，则不得按普通提前预取路径去源穴取空。任务规划需表达复用/换样策略，不能仅以项目索引变化推断必须换料。

### 计划绑定和状态

点检任务：请求待分配 → 目标批次已绑定 → 点检料准备中 → 已装夹 → 等待目标PC就绪 → 测试中 → 结果已记录 → 等待正常交换取出 → 样品已归还 → 完成；任何动作中断进入保留身份的暂停状态。

目标PC的模式状态与机械状态分开。满足当前普通测试已结束后，参数切换可以与允许的机械交换并行；启动点检必须同时满足正确物料已装夹、夹具测试条件满足、PC已确认目标模式/索引。恢复普通测试同理。不承诺软件重启时间总能被机械时间覆盖。

目标批次至少标识物理夹具/工站、访问或测试轮次、测试PC及被选中的穴位集合。三嘴一次两片交换只是执行分组，不等同于测试PC的一整轮测试。任务分配先覆盖目标PC所需整组穴位，再拆成两片动作，防止一个测试批次被两个计划拆开。

### 物料记录

在Product.MdDat增加普通/点检用途以及点检任务、样品、归还位置的关联；Clone也要保留。WS.MdDat或稳定的夹具物料记录保留相同关联。现有threeNozzleFixtureMaterials仅在内存中关联已放物料，新方案需跨交换访问保留，不可依赖会被下一次计划清空的临时字典作为唯一依据。双臂搬运、扫码绑定、测试结果更新不得覆盖点检用途。

点检穴位状态至少区分在盘、已预约、已取走、归还中和异常；装盘配置不是实时在盘证据。位置仍在但样品在夹具/吸嘴上时，不允许另一臂重复预取。盘共享范围在机械方案确定后决定锁的粒度。

### 按当前源文件划分

- UpDownLoad.ThreeNozzle.cs：在建立目标批次计划时绑定料源/样品；ThreeNozzlePreparePair按计划获取料位；放料提交身份；ThreeNozzlePickMaterial保留取出样品身份；ThreeNozzleUnloadCore按身份选择普通OK/NG或点检归还路径。
- ThreeNozzleSequence.cs：维持三嘴两片交换基本动作。新料源和卸料策略通过执行层处理，不复制另一套上下料状态机。
- ThreeNozzleCoordinator.cs：加入目标批次绑定/进入条件，保留双臂和转盘权限。点检接收线程不直接控制轴。
- Product.cs / WS.cs：保存普通与点检身份、目标测试轮次；点检结果记录与正常产量、良率、MES口径隔离。普通成品仍走现有规则。
- WS.cs / AutoChkDll.cs：接收已确认的点检触发、处理目标PC模式切换和结果；每PC保存独立计划及模式状态。旧全局isAutoChkMode会影响WS.MdDat.benable，新流程不得直接复用其全局屏蔽行为。
- 新增点检任务管理文件与点检盘配置：集中处理任务生命周期、请求去重、样品预约和回盘记录，避免散落到多个布尔量中。
- FrSys / FrProduct / FrRun：配置点检盘可达臂、穴位及样品映射；示教点检盘工艺位置；运行页显示待执行/已绑定批次、目标PC、模式切换等待、样品位置和结果。原手动开启可保留，但接入同一模组点检任务，禁止重复执行。环境点检界面保持原功能。

### 故障处理边界

请求尚未绑定可取消；已经拿到点检料则保留当前位置并走明确的归还/继续选择，不能简单删除任务。吸嘴取放结果不确定时沿用物料核对流程；正常生产无异常时不增加清料或停机步骤。重启后恢复前先核对持久记录与实际在机样品，不自动重新取同一穴。

### 分阶段落地

1. 确认触发与目标批次规则、点检盘结构、样品/项目/穴位映射。
2. 完成不连接运动的任务、身份、料源路由及模拟交换验证。
3. 接入真实点检盘取放，验证普通→点检→普通的三嘴交换和归还身份。
4. 接入匹配版本DLL/协议模式切换，联调两个PC不同响应时序及结果归属。
5. 验证现有生产、GRR、单嘴和旧点检入口不被破坏；新自动点检在特殊模式下的接受/延后规则单独明确。

验收重点：不中途清普通料；当前已取料身份不被请求改写；点检轮准确绑定；普通成品进入正常盘；点检样品归指定穴；不存在错误测试参数启动；请求重复不重复取样；完成后继续正常供料。
