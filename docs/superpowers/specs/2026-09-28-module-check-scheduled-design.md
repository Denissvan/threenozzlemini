# 定时模组点检自动化方案（当前需求）

状态：规划，未实施。依据2026-09-28用户明确需求，替代9月27日草案中仍待确定的触发、装料数量和归还要求。环境点检保持原功能。

## 已确认

- 电控定时主动发起，不以279/276作为本次自动流程的正常触发条件。
- 员工可设置模组点检时间。应在该时间之前一小时内发起模式切换，为点检留出执行时间。
- 电控发送点检模式，测试软件切换参数；就绪后，在后续某工站正常上下料轮次装入点检盘物料。
- 默认将点检料盘全部物料装入该工站进行点检。
- 点检面为AFC、DCC、OTP三选一。面选择与承载样品的工站选择是不同概念。
- 点检期间其他普通料继续正常上下料和测试，不清普通料。
- 点检完成后物料放回点检盘，不按OK/NG分流到普通成品盘。
- 用户已确认：点检工站具有独立测试程序，模式切换不影响其他工站。命令仅发送到目标工站对应测试程序。

## 时间设置设计建议

独立“模组自动点检”设置，不复用环境点检计时标志。界面提供启用、计划点检时间、提前启动分钟数（建议默认60，范围1至60）、点检面、承载工站和点检盘配置。计划时间T作为预留完成时间的调度目标；是否要求严格在T前完成仍待确认。触发窗口[T-60分钟,T)，建议在配置的提前时刻到达后尽早执行，不是到T才启动。

定时器仅创建待执行任务，不直接运动。每次计划使用日期/计划项作为唯一标识，持久记录已触发/执行/完成，避免重复Tick、重启或时间调整重复取料。窗口内重启且该计划未执行可登记；错过窗口显示逾期，具体补执行策略需明确，不静默当成已完成。

## 执行顺序

1. 提前窗口到达，建立模组点检任务并冻结点检面、点检盘样品清单、目标工站。
2. 先预约下一轮尚未预取的目标工站完整上料计划，锁定该轮料源为点检盘。若该轮已预取普通料，建议先正常完成这批，预约后一个完整轮次；不得切换程序后又启动已经预取的普通料。
3. 在目标程序当前普通测试已结束、该轮结果已保存且点检批次已预约后，发送SetFactoryMode；等待重启登录Ack，GetFactoryMode回读目标参数并确认测试通道就绪，再执行该轮点检上料。
4. 在正常交换中从点检盘取料并逐组装入工站；当前普通成品按原OK/NG规则卸盘，其他工站继续原流程。
5. 点检清单所有样品装入映射穴位且测试条件满足后，执行所选面的点检项目，使用既有模组点检接口读取/记录结果。
6. 每轮结束先检查逐工位结果是否有292。存在292则保留固定样品批次，转回上下料面执行工位换位并开始后续点检轮，不引入普通新料。无292且满足整次点检完成条件后，才卸回点检盘并切回普通料。归还建议按样品原穴，不按最终所在夹具穴位归还。
7. 目标测试程序恢复生产参数并确认就绪后，才启动该批普通料测试。全部点检样品归还、结果已记录、生产模式恢复后标记任务完成。

模式状态、物料状态分别管理，不能以一个全局isAutoChkMode标志控制全部工站。已确认测试程序按点检工站隔离；只向该工站对应程序发起模式切换和回读，其他工站保持原参数与任务。共享机械资源仍沿用现有转盘/双臂互锁，不承诺点检完全不占机械时间。

## 全盘上料与位置身份

点检盘保存有效样品穴位清单及其到目标工站穴位映射。默认全选全部配置有效样品，不能沿用普通供料仅取两颗就开始整轮测试的假设。三嘴每次两片只是搬运分组，任务完成装料的条件是整张清单已装入。奇数数量最后一组按单片动作处理。

配置校验：样品数不能超过该工站可用穴位，全部位置可达，映射不能重复。超过容量不能静默遗漏或自动分批，需调整配置或另行明确分批要求。取空、识别失败时不得当成全盘点检完成。

记录每个样品的源盘/穴、当前位置（嘴/夹具）、任务与点检面、结果及归还状态，普通料保留原去向。已归还样品不得重复放回。点检NG仍归点检盘并保留失败结果，是否允许恢复普通生产由质量处理规则明确。

## 点检面与协议的边界

文档只定义FactoryMode和CheckModeTemp，没有独立AFC/DCC/OTP面字段。AFC项目10001/10002/10003、光源项目20001/20002、色温项目3000/4000/5000不能仅凭名字构造完整面映射，尤其DCC并无独立命令索引。应核实已有测试参数/流程与各面的对应关系，建立经过确认的面→测试程序/项目列表映射。不得发明协议字段，亦不得误用环境点检面选择代替模组点检配置。

GetAutoCheckInfo为测试端已配置项目列表，不自动等同于当前所选面需要执行的全部项目；GetCheckModeResult结果归属和旧DLL30秒窗口问题仍需确认。

## 整轮测试机制与三个面的正确处理

转盘按用户确认顺序：上下料面POS0 → 左侧AFC面POS1 → OTP面POS2 → 右侧DCC面POS3 → 上下料面POS0。物理测试面与承载夹具的工站ID分开保存。

当前代码StartTestFlow启动一整轮；提前/后开图受PT_SET.turnon等条件控制，并非每面重新启动。WS.WaitTestResult接收中间sta和最终结果，机械按sta完成动作后调用NextTest通知测试程序继续。光箱MoveTo返回END时，现有代码将该面阶段标记NEXT，交由转盘流程推进。因此不能通过在“未选中面”简单跳过StartTestFlow实现单面点检，也不能伪造NextTest应答或最终OK。

推荐保留整轮握手机制，由目标点检参数定义实际点检项目；电控根据所选面校验步骤映射并沿用到位、光箱避让、转盘权限。非目标面如何通过，必须由经过确认的测试步骤表表达：哪些sta需要等待对应面、哪些表示本面结束、何时最终完成。若目标参数仍要求其他面动作，不能擅自略过；须先由测试端提供正确单面参数/步骤定义。

若测试在AFC已返回最终结果，立即查询并保存点检结果，但样品仍随夹具按既有转盘路径返回上下料面后归盘。“测试已完成”和“样品已归还”是不同状态；不因提前完成而让夹具逆转或提前进入上下料区域。

## 状态与数据设计

任务状态：待窗口 → 待目标批次 → 已预约 → 切换点检参数 → 待装料 → 装料中 → 整轮测试中 → 结果已记录/等待回盘 → 归还中 → 恢复生产参数 → 完成。机械归还与程序恢复可在核实资源安全后并行，完成条件仍需二者均成立。

所有任务统一保存：计划发生日期/计划ID、任务ID、目标工站ID及测试程序地址、点检面、目标交换轮次、确认过的点检参数索引、样品清单、每步进度、原生产模式、请求/应答CmdId及时间、点检结果。任务ID是电控本地身份；现协议CmdId仅匹配单次命令，不将其冒充测试轮次ID。

样品清单保存：样品ID、源盘/原穴、目标夹具穴位、当前位置、是否取起/装入/取出/归还、结果和异常。与Product.MdDat及WS.MdDat绑定并沿Clone/上下料交接保留；不能仅依赖一次访问结束就清空的threeNozzleFixtureMaterials字典。

提交规则：计划和盘穴预约先持久化；取放成功后更新物料位置及动作完成记录。进程中断或取放结果不确定时进入待核对，保留最后已确认动作及尚未确认动作，不自动重做整组取放。

## 三嘴料源与归还改动

ThreeNozzleEnsurePlan/Prefetch：对目标工站整个待测批次冻结任务和料源，再分成两片交换组；两条臂共享该批次的不可变映射，防止一臂普通料、一臂点检料误混。

ThreeNozzlePreparePair：普通任务使用原traybox_fd；点检任务按预约清单从点检盘取指定穴。点检盘是固定或移动仍由机械资料决定，采用对应就绪/移动动作，不强行复用普通料仓升降换盘。现有XT取放、逐嘴Z补偿和双臂避障继续使用。

放入夹具：逐件保存点检身份。整张点检清单未完成装入时，不发起整轮测试。点检批次其余未使用夹具穴明确为空/不参与测试，不自动补普通料。

ThreeNozzleUnloadCore：先看取出物料身份。普通成品按原res到OK/NG盘；点检样品即使NG也走点检盘归还路径。建议原穴归还；原穴被占则报警保留身份，不能找普通盘替代。

三种正常交换：普通→点检（取点检料，卸普通成品）；点检→普通（取普通料，卸点检样品）；点检项目间换样（按明确样品映射交换）。若多项目共用同一批样品，优先按测试参数完成整轮；需要多轮时明确留夹具重测或归盘再取，不默认去原盘取尚在夹具上的同一件样品。

保持现有UI结构，在模组点检设置区域改造，不将环境点检控件移入其中。

| 区域 | 控件/内容 | 规则 |
|---|---|---|
| 轮数限制 | 最大点检总轮数（含首次），默认8，范围1–8 | 本任务冻结上限；需重测但已达上限时报异常 |
| 定时计划 | 自动启用、计划时间列表、提前分钟数、下次触发显示 | 建议默认提前60分钟，范围1至60；日期跨午夜正确计算 |

| 点检料盘 | 盘配置入口、样品数、穴位与夹具映射表 | 默认全部有效样品；缺映射/超容量不允许启用 |

| 操作 | 保存设置、立即申请一次点检、查看记录 | 立即申请也走同一任务和预取边界，不直接运动 |

“保存配置”不等于“现场校准完成”。点检盘示教复用既有逐嘴补偿语义，给定可达机械臂、料位XY/工艺Z/U及样品排列；底层坐标数据待机械资料补齐。

## 与既有流程的改动边界

- 原模组点检的GetPcChkInfo/SetPcAutoChk/GetPcChkResult/SetPcPrductMod、StartTestFlow/WaitTestResult/NextTest作为复用入口，逐项核对返回码与作用工站后适配，不另造一套测试引擎。
- 原到时人工确认、PutModShowMsg例行上料确认改成任务条件；手动开启保留为同一任务的触发入口。原ClearMt路径不用于新自动模组点检。
- VAR.isAutoChkMode当前会影响非目标工站benable及若干统计/提示；改造时逐一用“当前工站/物料是否属于本次模组点检”替代新路径的全局判断，不在新任务开始时全机设置点检标志。
- 点检轮次、项目列表及结果按目标任务/测试程序保存，避免静态ListChkTemp被另一PC覆盖。目标工站若对应多个PC，全部需要的PC一致就绪后才启动，任一切换失败不带着不一致参数运行。
- 279/276保留其原提示语义，不作为新定时任务的普通触发源；需防止它们与已登记任务重复弹窗/清料。环境点检AutoInspectionParameter及光箱测量逻辑不改；仅在同时需要共享硬件时沿用现有互锁。
- 普通生产计数、NG分盘、条码、MES保持原逻辑；点检样品进入独立点检记录，不污染生产良率。点检数据MES上传口径沿用现场要求，不能自动套普通出货记录。

## 超时、异常和恢复建议

模式切换超时：先查询目标实际模式，不直接重复Set；保留任务，禁止目标PC以不明参数开始测试。其他工站能否持续循环仍受共享转盘既有安全条件约束，不声称单站故障时无限不停机。

测试结果：等原整轮完成条件，再读取点检结果并持久化，随后才恢复生产参数。现文档只有“最近一次结果”，应以确认过的初始化/清除和完成时序保证归属；无法保证则需要测试端补充定义。若旧30秒窗口仍有效，读取不能拖到物料回盘后。

点检NG：记录失败并将样品归还，不自动作为通过。建议由既有质量处置入口决定重试/恢复生产，不新增无限自动重试。归还失败则不能将任务标记完成。

跨日/重启/时钟调整：同一计划发生事件只创建一次；未执行逾期与执行超时分别显示。建议窗口内开机补登记、窗口外逾期由操作员选择立即申请，不在开机时无提示突然运动。停机状态只登记，不自动启动整机。

## 292驱动的固定样品换位（新增要求，优先于前文单轮结束即归还的描述）

### 已确认语义与代码差异

用户明确292代表对应工位要求换料；换料是同一承载工站内部样品换位置，不是从生产料盘换新件。每轮点检阶段工位需要不同的料，点检样品总数固定。当前UI/MotionCtrl的C#业务代码未发现292专门分支；设计器中的292为坐标等，与协议无关。该语义来自用户本次说明，不能将HTML未列明的字段假定已实现。

现有ThreeNozzleUnloadCore将res==0送OK、其他非负结果送NG盘，必须在它之前识别点检物料与292控制结果，防止样品误落普通NG盘。292不得作为普通NG触发换盘补料、普通NG统计或清空样品身份。最终测量值仍保存于本轮结果，不以清res丢掉历史。

### 推荐任务分支

整轮完成并保存逐工位结果 → 汇总292工位 → 有292：换位待执行 → 回上下料面并满足夹具打开条件 → 执行已持久化位置计划 → 全部目标落位核对 → 下一轮测试；无292：依据测试端整体完成条件决定继续项目或归还。没有292不自动等于点检PASS。

汇总须覆盖该工站本轮所有参与测试的PC/工位。不能某个PC先返回292就开始移动仍在其他PC测试的样品。重复读取同轮292只登记一次换位，任务号+轮次+工位结果快照共同识别，不能每次轮询增加轮次。

### 换位集合及轮次规则

推荐将“只要本轮出现292，就在该点检批次允许互换的全部工位做一次无原位循环移位”作为默认策略，这更符合每轮所有工位收到不同样品的要求。只对292工位做互换不足以保证非292工位也换样；仅一个工位报292时至少需要另一个合法伙伴。全组轮换范围仍需与测试端确认，特别是已经通过的工位是否允许参与并重测。

先生成位置映射，再运动，不能临时找第一个空穴。参与工位、样品、可达机械臂和样品适用性决定允许的映射。

例：四工位第一轮[A,B,C,D]，后续依次[B,C,D,A]、[C,D,A,B]、[D,A,B,C]。相邻轮每颗样品都换位置；前四轮每个工位见到四颗不同样品。简单两两互换两轮后即回到旧位置，不适合要求跨多轮不重复的场景。

应分别校验“不同于上一轮”和“本次点检阶段从未在该工位出现过”。建议保存全历史并按较严格的阶段内不重复规划，测试端须明确阶段边界及是否允许历史重复。N颗样品占N个工位时，在全部可互换的前提下最多N轮各工位样品不重复（包含首轮）；受双臂分区等限制时上限更低。达到上限仍有292，不循环复用伪装成新料，应提示无新组合并等待处理。只有一颗样品且仅一个可用工位时不可满足互换。

### 固定样品与三嘴的关系

不能复用普通生产“提前取两颗新料、交换后将旧料卸盘”的持续供料语义；点检盘空了可能代表样品正在夹具测试，不能视为空盘并换盘。

三嘴硬件仍可使用，但点检换位用两嘴暂存即可。以[A,B,C,D]变为[B,C,D,A]为例：
1. N1取工位1的A并暂存，工位1变空。
2. N2取工位2的B，放到空工位1。
3. N2取工位3的C，放到空工位2。
4. N2取工位4的D，放到空工位3。
5. N1把暂存A放到空工位4。
N3保持空闲。每次必须先确认目的位为空，验证取放及真空，提交对应身份再继续。四件每轮4取4放，无需额外点检样品，也不必每轮回点检盘。

该方法要求所用两只嘴均能到达其负责的源/目标位。现有GRR的N1保留第一件、N2搬后续件可复用运动思路，但其按最早空穴落料、bAutoChkOk过滤、普通NG落盘和清料分支不能原样套用。

### 双臂及备选动作

先建立机械可达性和允许互换分组，不能只按工位编号推断可达。各臂内合法组可独立循环，统一完成后才启动工站下一轮。若要求跨两臂区域交换且不存在已验证交接路径，不能直接安排空中交接。

备选：本工站全部点检样品先回各自原点检盘穴，核对归还完成后按新工位映射重新装入。每件一次卸回一次重装，约2N取+2N放，是直接换位N取+N放的两倍搬运次数，但仍是原固定样品，不需要备用新料。只有点检盘穴对负责目标位的机械臂可达时，才可作为跨臂中转方案；否则需修改分组或机械交接设计。

这里暂存的是本工站点检料，不清其他工站普通料。换位会占用上下料面时间，共享转盘仍按现有条件等待各面就绪，不承诺物理节拍完全不变。

### 身份和故障恢复

保存固定样品ID/原盘穴、每轮工位映射、已测试工位历史、292请求集合、规划目标和逐步动作日志。测试结果属于样品在本轮某工位的记录，不能仅跟工位号保存。换位完成后测试条码列表必须按新的工位→样品对应重新生成，不能保留旧工位条码。

轮换中不做普通新料预取；首次整盘装入和整次结束归还才访问点检盘，除非使用归盘重排备选动作。样品丢失/真空异常不能自动从生产盘补一颗继续，固定样品清单保持不变，异常核对后恢复。

换位进度按每一次取/放提交；中断时保留嘴上样品、空工位和下一目标。重启不重新计算一套轮换，也不再次执行已完成的292换位。样品全部落位、映射一致、相关吸嘴已空、夹具满足测试条件且本轮已准备完成后才再次StartTestFlow。

### UI及验收补充

运行页增加当前点检轮次/阶段、292待换位工位、当前工位→样品表、下一轮计划及已完成换位数。配置选择合法互换组/阶段内去重规则由工程设定，员工无需手排吸嘴动作。

重点用例：只有一个工位292；多个工位292；一台PC先完成另一台未完成；重复292应答；N=1/2/奇数/全盘；连续多轮不重复及组合耗尽；跨臂不可达；换位中断后续做；条码身份随位变化；292样品不落NG盘；整次结束按样品原穴归还；普通工站与环境点检不被模式变量误屏蔽。


## 已确认补充：292整批换位及16工位

用户已确认：任一工位出现292，允许该批全部点检样品循环换位。换位触发按本工站完整轮次汇总，不再仅对292工位挑伙伴；全部参与样品采用统一计划，下一轮重新测量。

代码证据：WS.cs的pc_id/testbox_id/md_sn均为4×16映射，构造函数按m<16创建物料记录，默认排列字段为2×8。方案按每个承载工站16工位建立完整映射；实际参与数量仍依据样品清单及有效工位。满配16颗且允许全体互换时，循环移位可实现最多16轮各工位不重复见料（含首轮）；机械分区限制下不能直接承诺此覆盖。

双臂分工不等同于前8位/后8位：ThreeNozzleModeOwnsPocket按零基index%8<4或>=4过滤，LOW对应1–4及9–12，HIGH对应5–8及13–16；实际哪条臂采用哪种分工须按FindMod配置确定。16工位是否做跨组大循环，或两组各自8位循环，需结合可达范围与覆盖要求确定，两者全历史覆盖能力不同。不得把能保存两臂坐标视作已经证明所有物理工位均可达。


## 最终确认的换位范围：双组各自循环

用户选择组内循环，不做16工位跨组大循环。按现有分组：LOW=[1,2,3,4,9,10,11,12]，HIGH=[5,6,7,8,13,14,15,16]。哪条臂执行哪个组按实际FindMod配置绑定，不固定猜测臂号。组内动作仍使用已有安全路径及避障条件。

任一工位出现292，整个点检批次的两组均执行一次换位；两组全部完成并核对物料位置后才允许开始下一轮，不能完成一组就先启动该组测试。

建议顺序按组内工位编号循环。LOW样品搬运方向：2→1、3→2、4→3、9→4、10→9、11→10、12→11、1→12。HIGH：6→5、7→6、8→7、13→8、14→13、15→14、16→15、5→16。

执行时每组N1先暂存组首位样品，N2依次把下一位置样品移入当前空位，最后N1放入组末空位；N3空闲。满配每组8取8放，两组共16取16放，无需每轮访问点检盘、无需备用样品。两臂可否同时运动由现有避障及实际路径决定，不以“各自分组”替代互锁。

初始映射记为第1轮，每次292触发后移位一次。每组8颗样品时，前8轮每个工位见到8颗不同样品；第9轮会重复第1轮。保存组内完整历史，不能声称覆盖另一个组的8颗样品。达到8轮或员工设定上限仍要求292时，不再换位或重测，按异常弹窗的继续/终止选择处理；继续也不突破轮数上限。

实际样品未满16时，计划根据已配置参与工位在本组内构造有效循环，不跨组补料。组内仅1颗样品且无其他合法交换伙伴时不满足同组互换，禁止声称换位完成；需先明确样品配置。最终归还仍按每颗样品原点检盘穴位，不按换位后工位编号归还。

## 已确认补充：轮结束结果、重启测试与轮数上限

用户明确所有点检结果均在本轮测试完成后返回；292也表示本轮已结束并要求换位重测。电控收齐目标工站本轮所有必要PC结果后处理，不因一台先返回就移动。

存在292且允许下一轮时：保存本轮结果 → 回到上下料面 → 两组各执行一次循环换位 → 校验全部样品新位置/条码及双臂退出 → 再次调用StartTestFlow启动下一轮。不能将292当作sta传给NextTest，也不在换位尚未完成时启动测试。

UI增加“最大点检总轮数（含首次）”，建议默认8，整数范围1–8。以包含首次的总轮数统一计数，避免“重测次数”含义导致第9轮。满配组的有效上限=min(员工设置,8)；若允许少于8样品的组并要求不重复，进一步受最小参与组样品数约束，配置阶段校验，不能在少料情况下宣称仍有8种无重复组合。

检查时机：每轮完整结果保存后，若需要292重测且当前轮数已达到有效上限，则弹窗“点检换位重测达到上限，本次点检异常结束”，不再换位、不调用下一轮StartTestFlow。比如上限3：第3轮仍有292时结束；上限8：第8轮仍有292时结束。不能等第9轮测完才报错。最后允许轮若正常通过，则正常完成，不因恰好达到上限而报错。

第1轮是初次测试；轮次在新轮启动被确认后推进。通信重发不能被算成新轮；启动响应不确定时进入核对，不盲目重发造成重复物理测试。员工在运行过程中修改上限仅影响后续任务，本任务保持创建时上限快照。

超限终态为异常，不伪装点检成功；弹窗显示工站、点检面、实际轮数/上限、292工位列表及样品当前位置。保持样品身份和原穴映射，待安全回到上下料面后按既定归还流程回点检盘。若无法自动安全归还，保留异常恢复状态；弹窗确认本身不等于样品已归还。NG/超限后允许员工明确选择继续生产，不要求点检必须通过；仍须完成样品归还和生产模式确认。关闭弹窗不等同于选择继续。

上述确认取代早期草案中关于292返回时机、换位后是否再次StartTestFlow以及第9轮允许重复的开放选项。


## 已确认补充：失败弹窗与人工继续/终止（2026-10-08）

用户要求所有失败均弹窗提示继续或终止；点检不通过不构成永久禁止恢复普通生产的条件。员工可以在点检NG或重测超限后选择继续生产，保留失败结果及人工选择记录，不把人工放行改写成点检通过。

弹窗的继续行为根据失败阶段明确显示，不能同一个“继续”在不同场景中无说明地跳步骤：

| 失败类别 | 继续的含义 | 终止的含义 |
|---|---|---|
| 本次点检已结束但结果NG | 结束本次点检，归还样品，恢复生产参数并确认后继续普通生产 | 停止本次自动执行，保留NG、样品位置及当前进度，转人工处理 |
| 292已达轮数上限 | 不再换位/重测，归还样品并恢复生产；结果保留超限异常 | 停止本次自动执行并保留现场，转人工处理 |
| 点检模式切换/通讯/结果读取失败 | 从当前失败步骤核对状态后重试；启动状态不明确先查询核对，不盲目重复StartTestFlow | 停止继续调度，保留参数状态、物料与轮次 |
| 取料、放料、换位失败 | 人工处理后先核对实际嘴/夹具/盘穴状态，从确定的未完成动作继续 | 停止动作，保留持料真空、样品身份及换位进度，不自动清空 |
| 样品归还失败 | 核对已归还与嘴上样品，继续未完成的归还 | 停止归还，保留未归还清单和当前位置 |
| 恢复生产参数失败 | 重试/回读确认生产参数；确认前不启动普通料测试 | 停止后续自动执行，保留恢复未完成状态 |

弹窗正文必须说明“继续后将重试哪一步”或“继续后将结束点检并恢复生产”，必要时按钮标为“继续（重试）”/“继续生产”。显示工站、面、轮数、错误原因、样品位置；处理同一任务失败只保留一个有效操作决策，避免两PC/双臂同时弹窗导致重复续做。

等待选择期间冻结失败任务的新动作，不重新派发取料/换位，不清除样品记录。终止不是机械急停的替代定义；按现有受控停止/异常流程处理运动及持料。后续人工恢复必须进入原未完成任务的核对流程，不能把任务删除后当新一轮启动。共享转盘是否继续仍服从现有机械互锁。

只有用户明确点击继续才执行对应继续路径。弹窗关闭或没有选择均不视为授权继续。若继续后条件仍不满足，再提示相应失败，不伪造动作成功或跳过生产模式确认。

新增验收：点检NG允许人工选择归还并恢复生产且保留NG；超限继续不产生额外一轮；每类失败都有继续/终止入口；终止不释放持料或抹去进度；归还重试不重复放已归还样品；通讯重试不重复启动一轮；生产模式未确认不能用点检参数启动普通料。

## 已确认补充：通信分工、点检项推进与借用待测盘（2026-10-26）

### 通信分工

点检对电控而言与普通测试相同，测试端自行处于点检或生产参数。两套DLL分工固定：

- PUCFTestServiceCall.dll 只用于模式切换：`SetFactoryMode(Check)` 通知目标工站PC进入点检；`GetFactoryMode` 回读确认；点检结束后由电控发送 `SetFactoryMode(Product)` 并回读确认。只发往目标工站对应PC。
- dllforcomv8 负责其余全部：StartTestFlow（含条码）、按sta定位、NextTest、逐工位结果（0/292/NG）、292换位后带新条码重新StartTestFlow。逐工位结果随握手与本轮条码绑定（测试端收到启动即复位结果区为-1），不存在结果归属和30 s窗口问题。
- 不使用 GetCheckModeResult，不使用 GetAutoCheckInfo；原 ListChkTemp/AutoChkCnt 逐项切换与计数逻辑不进入新流程。

### 点检项推进：一轮跑完所有项

测试端一次进入点检模式后不重启，在同一轮内依次完成全部点检项，所需光箱位置通过sta请求，全部完成后返回一次sta=0与逐工位结果。电控按结果处理：全部为0 → 点检通过；存在292 → 整批换位，带新条码重新StartTestFlow；存在NG → 失败弹窗。292轮数上限按“轮”计，与点检项无交叉。

### dllforcomv8侧实现检查点

1. 292重新启动前确认该PC结果标志已为MARK_END（GetInfo.result_mark）。DLL的StartTestFlow在标志非END时直接返回OK而不启动（“流程进行中，无需重新启动”），上一轮最终NextTest(0)握手未完成就重启会静默失败。
2. SetFactoryMode后约5 s重启期间禁止StartTestFlow（DLL只等ACK 1 s，WS仅重发一次）。须GetFactoryMode回读为点检参数且GetStatus心跳恢复后才上料/启动。心跳只证明在线，不证明参数，回读不可省。
3. 重启期间WS.GetStatus会把该PC置LINK_ERR；需确认主循环对LINK_ERR的处理，必要时在切换窗口内屏蔽该PC联机报警。
4. 切换点检时记录实际切换的PC，恢复生产按该记录逐台发送并回读，不依赖当时是否有启用物料（现有SetPcPrductMod默认bcheckEnable=true，工站空时会漏发）。
5. PUCF按PC_IP寻址，dllforcomv8按PC_ID寻址，二者须指向同一物理PC。任务启动前校验目标工站PC_ID与IP一一对应；核对现有代码PC2地址取list_md[10]而Pc2Enable取list_md[9]的不一致。
6. StartTestFlow开头ResetWholeStationTestState会把非空工位res重置为待测，292及本轮结果必须在此之前写入任务记录。条码串按list_md顺序拼接，换位沿用GRR分支条码随料（md.bardcode = xt.XtMd.bardcode）即可保证新条码正确。

### 点检盘：结构件到位前借用待测盘

- 点检盘作为独立Tray配置（行列、每臂tl/bl/tr三点示教，复用Product.Tray.CreatePos），增加参数“借用待测盘/独立点检盘”。结构件到位后只需重新示教并恢复待测盘穴位，不改代码。
- 借用期间：在待测盘上划出约1/3区域（穴数≥样品数，满配16）示教为点检盘；该区域在待测盘产品配置中取消穴位启用（isDisable），普通生产不取不退。
- 借用期间必须阻止换盘带走样品：点检任务进行中（预约到全部归还）禁止待测盘自动换盘（ThreeNozzleEnsureTray → Tray_Action），待测区取空则报警等待；非任务期间换盘前弹窗提示员工将样品转移到新盘点检区并确认。
- 借用期间点检区在待测盘内，料盘轴行程不变。正式点检盘示教后由软件遍历点检盘/待测盘全部穴、两臂、目标夹具穴，按CaliPos公式计算所需料盘轴行程极值并与软限位比对；允许行程仍按机械限位确认后填参数。CaliPos/FindNextTrayPosX1上限钳位一并实现。
