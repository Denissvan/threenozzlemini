# 三吸嘴技改实现记录

修改目录：`MINI三吸嘴技改`。原 `MINI3.0.0.17` 未修改。本次没有连接控制器或运行机台。

## 运行路径

1. `WS.SetupForFeed` 完成翻到上下料方向后启动两臂预取，与开盖重叠；若工站已在上下料位，则由主线程补发同一请求，不重复取料。
2. 每臂 N2、N3 预取两颗待测料，N1 空置。工站确认开盖完成且 `REDAYFORUPDOWNLOAD` 后才允许进入治具区。
3. 每组执行：N1 取旧 A → N2 放新 A → N2 取旧 B → N3 放新 B。原每组两片、两臂分区及单臂运行的穴位归属保持。
4. 中间组先把成品放盘，再补下一组新料。末组全 Z 抬升、退到安全位后，交换任务返回；总流程按原要求执行夹具扫码、合盖检查等，再释放尾部落盘任务。
5. 普通模式末组落盘与合盖/翻转/转盘动作重叠。开启合盖拍照或 Hall 时，先完成会使用机械臂或限制时序的原检查，再释放落盘，因此这些模式的重叠窗口较小。
6. 下一工站预取必须等待上一轮落盘完成。新落盘方法不调用会重返治具的旧 `FlyCamToTray` 路径。

空治具跳过取成品；清料不再获取新料，已预取的物料完成本组处置；禁用穴位不补新料。预取后穴位被连续 NG 逻辑禁用时，按保存的源盘、源穴和取料坐标退回该嘴的新料；源盘已更换则沿用人工取走确认，不能把料放进新盘同编号穴位。

## 原生产功能保留要求（2026-09-25）

用户明确要求保留原生产所有功能，不能用启动拒绝或要求关闭工艺开关代替适配。逐嘴适配分为以下模块：

| 模块 | 处理职责 |
| --- | --- |
| `UpDownLoad.ThreeNozzle.Scanning.cs` | 上/下扫码、附加扫码、指定嘴马达扫码及供料盘二维码防呆；码绑定到实际物料和穴位 |
| `UpDownLoad.ThreeNozzle.Checks.cs` | 原取前/放后扫码检查、放偏复检、DW成品回检及2222分流；末组离场前完成DW检查 |
| `UpDownLoad.ThreeNozzle.Modes.cs` | GRR同批换位、原固定单嘴选择、自动点检合格穴筛选；GRR不改为普通生产换新料 |
| `UpDownLoad.ThreeNozzle.Returns.cs` | 指定嘴退回原盘、原穴，或原盘已更换后的人工移除确认 |
| `UpDownLoad.ThreeNozzle.PickRecovery.cs` | 取料失败重吸、跳料、换盘、清料与人工空穴确认 |
| `UpDownLoad.ThreeNozzle.TrayVision.cs` | 空盘首颗拍照、两臂共用同盘补偿，以及重拍/换盘/停止选择 |
| `MT.ContactOffset.cs` | 指定嘴接触偏移，另外两根Z必须在安全高度，保留原运动互斥与限位检查 |

普通三嘴交换、单嘴和GRR使用各自的动作顺序；原点检、Hall、合盖后检查及测试计数仍由原总协调流程控制。复检不通过时用刚放空的新料嘴重取NG，仅卸该嘴，再补该穴，其他嘴身份不动。重取、落盘、补料进度分别保存，暂停续做不重复取放。

第三嘴需要独立视觉和马达扫码标定；这些现场数据不能从原第二嘴推算，缺失时应明确报参数错误。

物理取放中断不清空追踪记录，不盲目重新取放。2026-09-27 按用户要求撤回新增的人工异常对账按钮和 ThreeNozzleRecovery 专用实现；上下料核心状态保护保留。本阶段不新增异常恢复 UI。
