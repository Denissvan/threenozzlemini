# 三嘴旋转中心与飞拍偏差标定实现/验证记录

## 实现范围

- `RotAndFly.cs` 的六嘴下拉框以臂/槽位/配置ID显示，旋转中心按实际 `XT.SlotIndex` 查找 `1_XtSharp`、`2_XtSharp`、`3_XtSharp`。模板缺失在运动前拒绝，未复制模板或数值。
- `Cam.CalRotCenter` 增加可选运动委托，旧调用沿用原委托；本页传入当前嘴独立 `ax_u`，不临时重绑共享 `Cam.MoveHandle`。拟合仍保留原算法、20点/两次标定和原RMSE门限。采点和拟合图形回到UI线程显示。
- 本页运动通过后台线程持有 `NozzleZCalibrationMotion.RunExclusive`，页面除停止外禁用，停止调用公共 `Cancel`。`Cam.Live` 在其他线程持有标定门禁时禁止启动实时，仍允许停止实时。
- 新增 `RotAndFly.Calibration.cs`：三嘴静拍各自模板，前/后治具独立静拍，按真实Y排序各相机的触发任务。原始飞拍得偏差，修正飞拍得残差；两次结果、计数、任务身份、有效值和触发关闭均成功后才保存。没有伪造 `XtMd`，没有释放真空，也不把治具片数用作嘴数。
- small或模式2保留索引7/15，模式1保留6/14，模式3保留15，模式4保留7。单排模式仍测本臂三只嘴，仅更新实际测到的工站排偏差，另一排保留原值。
- 三嘴 `xt_cap_ofs` 独立写回；前后排 `ws_cap_near_ofs/ws_cap_far_ofs` 按本臂共享原结构保存。第二次复测不覆盖第一次偏差。飞拍标定不改 `st_cap_pos`，不将动态偏差带入定拍。

## 运行链路边界

当前三嘴生产 `ThreeNozzlePrepareScanning` 仍调用逐嘴 `DwCamAction` 定拍；旧 `FlyToWs/FlyCfg` 的双嘴生产路径未被本次替换或启用。本次提供的是三嘴飞拍标定入口。保存飞拍偏差不能解读为三嘴生产已切换到飞拍。

本流程只做抬Z后的XY/U与拍照，不做工艺接触Z下降。因此没有对拍照坐标或旋转中心误差字段套用Z补偿。旋转中心 `st_rol.z` 仍是拟合误差。

## 离线验证

- `tests/three-nozzle-rot-fly-calibration-regression.ps1`：先在原实现确认旧固定双嘴数组导致失败，改后通过。
- `tests/three-nozzle-rot-fly-offline-tests.ps1`：使用真实新增partial，链接独立运动/相机桩，完全不加载主程序或硬件SDK；32项通过。覆盖所有治具模式、N3/任务/实际Y逆序映射、每嘴修正触发位置、残差与偏差分离、缺模板/未吸持/视觉NG/计数不符/NaN/触发关闭失败拒绝，以及五行结果完整显示、后台动作登记双臂16轴与取消停止。
- 离线WinForms表格已渲染检查：原尺寸794×289内，455×108结果表包含N1/N2/N3/前排/后排，默认缩放不用滚动。该图仅验证新增结果表与停止按钮，不等同完整宿主页或不同DPI实机验证。
- 整库构建由主任务统一执行；本记录不代替其构建结果。

## 现场尚须核对

1. 两臂六嘴各自真正训练过的旋转与模组模板、独立U轴方向、相机标定和真实旋转中心；新嘴缺模板会拒绝，软件不会生成标定数据。
2. 飞拍前本臂每嘴吸持真实标定件，按当前模式准备治具。核对三嘴拍照Y、该次治具X一致、Y行程内起点（最小触发点前180mm）/终点（最大触发点后50mm）和真实软限位。距离沿用旧流程量级，不能仅凭离线代码验证物理空间。
3. Hcmp端口/相机输入计数、最小触发间隔、图像与物理嘴/治具关联，以及停止/相机NG/触发关闭故障时的行为。离线桩不验证控制器时序。
4. 查看复测残差并按现场规定精度验收。本次未凭空设置飞拍合格公差；页面明确提示核对残差，保存完成不等于精度验收通过。
5. 原 `XT.SaveHwCfg` 使用既有系统INI存储，没有事务返回值；断电/写盘权限等持久化故障仍需按整机配置验收流程验证。
6. 完整系统校准宿主页与100%/125%/150%DPI视觉布局需现场复核。

本次没有启动主程序、没有连接/运动设备、没有对任何嘴执行真实标定。
